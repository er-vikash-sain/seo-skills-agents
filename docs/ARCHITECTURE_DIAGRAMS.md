## 🔄 3. TASK LIFECYCLE STATE MACHINE DIAGRAM

The State Machine diagram defines the strict, immutable state transitions for every task execution package (`task_spec.json` & `task_changelog.md`).

```mermaid
stateDiagram-v2
    [*] --> Created: Task spec generated by Planner
    Created --> Planned: Registered in tracking_index.json
    Planned --> Assigned: Routed to Subagent / Skill worker
    Assigned --> Executing: Worker runs task execution
    Executing --> Validation: Output written to task_artifacts/
    
    Validation --> ReworkRequired: Fails Validator / Provenance Gate
    ReworkRequired --> Executing: Retry execution (Max 3 attempts)
    ReworkRequired --> Escalated: Exceeds 3 retries (Circuit Breaker)
    
    Validation --> PendingApproval: Passes Validator & requires HITL sign-off
    PendingApproval --> Approved: Human Operator authorizes release
    PendingApproval --> Rejected: Human Operator requests revisions
    Rejected --> Executing: Rework with operator feedback
    
    Approved --> Completed: State merged into tracking_index.json
    Completed --> Archived: End-of-month rollover to archive/{year}/{month}/
    Archived --> [*]
```
